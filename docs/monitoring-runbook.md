# Monitoring runbook

## Stack

| Component | Role |
|---|---|
| Prometheus | Collects metrics from Kubernetes and the worker nodes |
| Node Exporter | Installed on the nodes by Ansible, scraped through `additional-scrape-configs` |
| kube-state-metrics | Pod and deployment state, including resource limits |
| Grafana | Dashboards |
| Alertmanager | Sends alerts to Slack channel `#alerts` |

All of it runs in the `monitoring` namespace, deployed by the `kube-prometheus-stack` ArgoCD Application.

## Access

Use one terminal for each port-forward.

```bash
# Grafana: http://localhost:3000   user: admin
kubectl -n monitoring port-forward svc/kube-prometheus-stack-grafana 3000:80
kubectl -n monitoring get secret grafana-admin -o jsonpath='{.data.admin-password}' | base64 -d; echo

# Prometheus: http://localhost:9090/alerts
kubectl -n monitoring port-forward svc/kube-prometheus-stack-prometheus 9090:9090

# Alertmanager: http://localhost:9093
kubectl -n monitoring port-forward svc/kube-prometheus-stack-alertmanager 9093:9093
```

Useful Grafana dashboard: **Kubernetes / Compute Resources / Pod**. Choose the namespace and pod, set the time range to the last 30 minutes, and read the memory panel against the limit.

## Alerts and what to do

| Alert | Meaning | First checks |
|---|---|---|
| `NodeExporterDown` | Prometheus cannot scrape a node (5m) | `systemctl status node_exporter` on the node, security group on port 9100, node IPs in `rendered/node-scrape-configs.yml` (they change after a rebuild) |
| `HighNodeCpu` | Node CPU above 85% for 10m | `kubectl top nodes`, `kubectl top pods -A`, check HPA and recent deploys |
| `LowNodeMemory` | Under 10% node memory free for 10m | `kubectl top pods -A --sort-by=memory`, look for a growing pod |
| `PodMemoryHigh` | A pod uses over 80% of its memory limit for 2m | See below |
| `Watchdog` | Always firing on purpose. It proves the alert pipeline works | Only investigate if it **stops** firing |
| `InfoInhibitor` | Always firing on purpose. Hides low-level alerts | Ignore |

### Responding to `PodMemoryHigh`

```bash
kubectl -n <ns> top pod
kubectl -n <ns> get pods                                   # restarts? OOMKilled?
kubectl -n <ns> describe pod <pod> | tail -20
kubectl -n <ns> get deploy <name> -o jsonpath='{.spec.template.spec.containers[0].resources}'; echo
```
- If the limit was changed by mistake, `git revert` the commit and push. ArgoCD fixes it.
- If the app really needs more memory, raise the limit in the values file and push.
- If memory keeps growing, treat it as a leak: collect the trend in Grafana and escalate to the service owner.

## Testing the Slack path

```bash
kubectl -n monitoring port-forward svc/kube-prometheus-stack-alertmanager 9093:9093
# second terminal
curl -s -X POST http://localhost:9093/api/v2/alerts -H 'Content-Type: application/json' \
  -d '[{"labels":{"alertname":"SlackTest","severity":"critical","namespace":"staging"},"annotations":{"summary":"Test alert"}}]'
```
A message should appear in `#alerts` within a minute or two.

## Changing alerts and the Slack config

Alert rules and the Alertmanager config are generated by Ansible (repo `k8s-ansible-config`, role `alertmanager-config`). Edit the template there, run the playbook, and the config is re-rendered. After changing the Alertmanager config, update the Secret:

```bash
kubectl -n monitoring create secret generic alertmanager-slack-config \
  --from-file=alertmanager.yaml=rendered/alertmanager.yaml --dry-run=client -o yaml | kubectl apply -f -
```

## Troubleshooting

| Symptom | Check |
|---|---|
| No Alertmanager pod | `kubectl -n monitoring describe alertmanager`. A bad config Secret is the usual cause (for example an invalid duration) |
| `kube-prometheus-stack` is `Degraded` | Give it a few minutes after install, then check the Alertmanager pod and the three Secrets |
| Test alert does not reach Slack | Check the Alertmanager logs and that the webhook in the Secret is correct (never print the file) |
| Prometheus shows no node targets | `additional-scrape-configs` Secret missing or the node IPs are stale. Re-run Ansible and recreate the Secret |
| TLS "bad certificate" lines in the operator log at start-up | Harmless noise while the admission webhook starts |
